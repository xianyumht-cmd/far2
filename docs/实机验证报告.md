## 6. 已知风险

- 移植子服务里的活动 ID（如 `2026081201` 青梅、`2026081800` 七夕、`2026090900` 公益红花）
  都是上游抓包时的活动号，**活动过期后接口会返回业务错误**，这属于正常表现（fail-closed，
  不会乱写）；要跟新活动就得重新抓选择器。
- 天气活动依赖好友地块扫描，成本较高，默认不在每日编排里自动跑。
- 扫码得到的 `authCode` 只能用于建号一次，过期需重新扫码。

### 7.4 登录态自动化（本机两个 QQ 的场景）

问题：本机登录了两个 QQ，用 `tencent://` 打开农场小程序时 QQ 会弹「选择账号」，
需要手动点，会打断无人值守。

落地两个工具：

| 工具 | 作用 |
| --- | --- |
| `tools/qq-account-picker.js` | UI Automation：找到「选择账号」窗口 → 选中目标 UIN → 点「确定」；另有 `close-farm` 只关 QQ 的农场窗口（不动微信的） |
| `tools/capture-code.js` | 一条命令完成：起弹窗看护 → 关掉已开的 QQ 农场窗口（否则 QQ 只聚焦旧窗口不会重新执行 game.js）→ 采集 fresh Code → 可选 `--apply` 回写账号并启动 worker |

实测（无需人工点击）：

```text
CLOSE_FARM closed=0
PICKER (no output)          ← 本次没弹窗
CAPTURE ok
CODE f5e0...9e05 (len=32)
APPLY account=1 start={"ok":true}
RESULT applied
```

注意两点（真实行为，不是缺陷）：

1. 采集 Code 必须让小程序**重新加载** game.js——所以会短暂打开一个农场窗口，
   采到后由脚本自己 `exitMiniProgram()` 关掉；只要不需要刷新 Code，就不会有任何窗口动作。
2. 同一账号同时只能有一个有效会话：如果你自己开着这个号的农场窗口，我们 worker 登录后
   两边会互相踢。要无人值守，就让 worker 独占该账号，别同时手动开着同一个号的农场。


### 7.5 实测踩到的坑与修复：QQ 会用「另一个号」打开小程序

复现：采集 Code 时 `qq.login()` 回来的 Code 落到了 `miniapp/fs/447677756/.../_code.txt`
（即 QQ 用 447677756 打开了农场），而脚本还在找 2320006072 的目录 → 判定「没采到」。

修复（`tools/capture-code.js`）：采集后**扫描所有 UIN 目录**取最新 `_code.txt`，
按实际 UIN 绑定：有账号就更新 code，没有就建号，然后启动；
并在日志里打印 `ACTUAL_UIN` + 不一致时 `WARN QQ 实际打开的是 X（不是请求的 Y）`。

这样无论 QQ 弹不弹「选择账号」、最后开的是哪个号，都能正确落到对应账号上，
不需要人工点选；要指定账号时，关掉另一个号的农场窗口即可（同账号只能一个会话）。

   `miniapp/fs/<uin>/1112386029/usr/_code.txt`，哪个号被打开就把码写进哪个号的账号记录，
   不一致打 `WARN`。

### 8.2 微信通道：环境打通了，卡在 WMPF 版本

| 步骤 | 结果 |
| --- | --- |
| 依赖安装 | ✅ 用 Node 20 工具链（`.toolchain/node20`）装 `frida@17.3.2`，拿到 118MB 预编译 `frida_binding.node`；Node 24 无预编译会退回源码编译（缺 Python/MSVC） |
| frida 17 ESM 适配 | ✅ `wechat-wmpf-native-capture.js` / `wechat-wmpf-resident-capture.js` 的 `require('frida')` 改成动态 `import('frida')`（CJS 会 `ERR_REQUIRE_ESM`） |

| 打开微信农场 | ✅ `weixin://dl/business/?appid=wx5306c5978fdb76e4&path=` 直接拉起小程序窗口（pid 18280） |
| **attach WMPF host** | ❌ `wechat_resident_wmpf_host_missing` |

原因：`wechat-wmpf-native-capture.js` 把宿主版本和内存偏移写死了：

```text
EXPECTED_WMPF_VERSION = 25297
```

**不是 25297 那个构建**。所以：

- 版本门直接判 `host_missing`；
- 即使强行绕过版本门，偏移也是错的，会写坏宿主进程（不能这么干）。
