# FAR2 与上游更新日志对照结论（2026-08-18）

> 状态：**当前结论 / 暂停继续追版本升级**
>
> 对照来源：`https://gitee.com/xlzcandy/qq-classic-farm-update-log`
>
> FAR2 仓库：`xianyumht-cmd/far2`

## 1. 当前决定

2026-08-18 对 FAR2 与上游后续更新日志重新核对后，当前决定：

**暂时不继续为了“追平版本号/功能清单”而升级 FAR2。**

原因：FAR2 当前最重要的 QQ 农场长期无人值守挂机能力已经基本追平，部分核心链已经超过日志版本。继续投入的主要对象已经变成微信、活动写操作、装扮、完整商店等周边能力，对当前实际使用价值有限。

后续默认策略：

1. 以稳定挂机为第一优先级；
2. 没有真实使用需求，不为了对齐上游版本机械补功能；
3. 只有出现真实故障、游戏协议变化、核心挂机能力退化，或者用户明确提出新需求时才继续开发；
4. 秒偷、蹲守、自动刷变异等上游自己后续删除/判废的功能不追；
5. 代理/节点/私有云体系不作为 FAR2 当前目标。

## 2. FAR2 当前已经追平或超过的核心能力

### QQ 登录 / Code / 无人值守

- FAR2Farm Windows 后台服务；
- `FAR2CodeAgent-<UIN>` 交互式 Code Agent；
- exact-UIN Provider；
- WS400 / kickout 事件驱动刷新 Code；
- 新 Code 验证后替换旧 Worker；
- Farm 自动恢复登录；
- 不依赖固定小时主动重登；
- 浏览器无需保持打开。

这套链路比上游日志中的“定时刷新 Code / 辅助软件保持 QQ 区可用”更适合 FAR2 当前本机无人值守架构。

### 好友 / 偷菜 / 帮助

- QQ 完整好友关系自动采集；
- 已实机得到 103 GID / 275 openId，并进入有效农场好友池；
- 偷菜、帮助、浇水、除草、除虫、捣乱主链已具备；
- 护主犬好友状态识别；
- 护主犬好友优先帮助；
- 经验满后普通帮助目标自动退避，避免无意义空转；
- 偷菜空闲状态低噪音可观测。

### 农田 / 种植

- 单土地铲除；
- 单土地普通肥 / 有机肥；
- 一键铲除；
- Lv5 紫土地分类；
- 2x2 master/slave 占地识别；
- 独立 2x2 优先种植与预留；
- 2x2 施肥链；
- 土地季节数、倒计时等展示；
- 作物变异只读展示。

### 图鉴 / 商店 / 动态作物

- 作物图鉴正式读取；
- 种子商店读取；
- 图鉴缺失种子安全购买；
- 当前运行分支还进一步做了启动前 Bag + 完整图鉴 + Activity + Shop 同步和 Crop Registry；
- 已通过官方运行时 Plant 配置证据识别动态作物身份和 1x1 / 2x2 footprint；
- 活动/特殊种子可以优先消耗背包已有库存，不再只靠手工补 seedId；
- 未证明 footprint 的种子 fail-closed，不盲种。

### 狗狗 / 宠物

- 自己的护主犬状态读取；
- 好友护主犬识别；
- 护主犬优先帮助；
- 宠物商店安全购买链；
- 狗粮信息读取；
- 狗粮单次喂食写链已经真实 E2E 验证。

### 个人 / 展示

- 个人生涯只读；
- 头像框库存只读；
- 运行健康中心；
- 多账号日志/状态按账号隔离。

### 活动发现

- 通用 `ActivityService.List`；
- `GetGroup` 深度只读发现；
- 可识别 random shop / exchange shop / draw pool / seed-like IDs 等结构；
- 当前未知活动保持只读，不猜写协议。

## 3. 与上游日志相比仍然明显缺少的内容

这些属于“有差距，但当前不值得为了对齐而主动开发”的能力。

### A. 活动自动执行

当前 FAR2 能发现活动结构，但多数活动仍不能自动：

- 领取；
- 兑换；
- 抽奖；
- 限时活动商店购买；
- 节气礼包；
- 助威活动；
- 钻石活动礼包；
- 神秘商店；
- 南瓜/其他限时活动写操作。

如果未来要补，必须继续遵守：官方 service/method、稳定 wire、字段语义、写前条件、写后验证全部证明后才开放自动写入。

### B. 微信好友体系

当前 FAR2 的生产主线是 QQ，微信侧仍明显弱于日志版本：

- 好友申请列表产品化；
- 按等级自动同意/拒绝；
- 微信删除好友；
- 按等级批量删除；
- 删除时判断护主犬；
- 排除黑名单；
- 微信长期重连/无限重连等。

当前没有实际微信生产需求，因此不作为开发优先级。

### C. 装扮 / 头像框完整写链

- 装扮商城；
- 头像框购买；
- 当前头像框穿戴；
- 狗窝/装扮同步；
- 完整外观管理。

FAR2 目前主要停留在头像框库存只读。

### D. 一些次要功能

- 背包种子/果实锁定、解锁；
- 收获延迟独立配置；
- 施肥延迟独立配置；
- 指定好友放黄金虫；
- 自定义延迟除黄金虫；
- 邮箱掉线提醒；
- 找回密码；
- 部分礼包批量使用 UI/上限体验。

这些都不是当前挂机稳定性的关键路径。

## 4. 不再作为差距追赶的功能

以下功能即使上游历史版本出现过，也不作为 FAR2 当前目标：

- 秒偷；
- 指定好友蹲守；
- 自动刷变异；
- 为了防护而增加复杂代理/节点体系；
- 为了对齐私有云版本而重做当前已经稳定的 QQ 本机 Provider/CodeManager 架构。

## 5. 当前总体判断

如果按“上游所有周边功能 100% 覆盖”计算，FAR2 仍然不是 100%。

但如果按当前真正使用的 **QQ 农场长期无人值守挂机核心能力** 计算：

**FAR2 已经基本追平，并在 Code 自动恢复、完整好友池、动态作物发现、安全写入边界等方面超过上游日志描述的方案。**

因此 2026-08-18 起默认不再继续追版本升级。

## 6. 以后再次评估时的触发条件

只有出现以下情况之一才重新打开差异审计：

1. QQ 农场协议更新导致当前核心挂机链失效；
2. Code 自动恢复、好友采集、偷菜、种植等核心能力出现真实回归；
3. 新活动奖励价值足够高，确实需要自动参加/领取；
4. 用户实际开始使用微信农场；
5. 用户明确需要装扮、头像框穿戴、黄金虫等具体功能；
6. 上游出现新的、对当前实际挂机价值明显高的能力。

否则以“稳定使用，不继续扩功能”为默认结论。
