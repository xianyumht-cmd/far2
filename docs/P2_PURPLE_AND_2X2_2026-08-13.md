# FAR2 P2B/P2C — 紫土地与背包 2x2 种植 — 2026-08-13

状态：**SOURCE REVIEW IN PROGRESS / LIVE ACCEPTANCE PENDING**

## 已由实机确认

P2A Windows 页面已确认：

- 土地 #1~#8 当前返回 `level=5`；
- 页面显示为紫土地；
- 后续公开实现也明确 `level=5 => purple`、`level=4 => gold`。

因此 P2B 不再把 Lv5 当作临时视觉猜测。

## P2B：紫土地运行时支持

目标：

- Lv5 在施肥过滤中正式归类为 `purple`；
- Lv4 保持 `gold`；
- 旧版本只有 `gold/black/red/normal` 四类，历史“四类全选”在运行时自动补 `purple`，避免升级后现有账号突然漏施 Lv5；
- 本轮不要求用户重存设置。

设置页独立勾选“紫土地”属于后续 UI 收口，不阻塞运行时兼容。

## P2C：背包 2x2 种植首版

当前 FAR2 的问题：

- `bag_priority` 以前显式过滤 `plantSize !== 1`；
- 旧 `Plant.json` 还缺少至少一个现实存在的 2x2 种子元数据；
- 因此用户背包已有 2x2 种子仍会被跳过，随后回退到商店购买 1x1。

本轮首版边界：

1. 已知种子 `20046`（爱心果）在旧 `Plant.json` 缺失时按 `2x2` fallback 识别；
2. fallback 只影响按 seedId / 背包识别，不注入商店自动候选；
3. `bag_priority` 先处理背包中的 2x2，再处理 1x1；
4. 只使用当前已经完整空闲的合法 2x2 组合，不主动铲除仍在生长的作物；
5. 24 块地按 4 列 x 6 行计算，Plant 请求一次发送 4 个 landId；
6. 回包必须验证 master 的 3 个 slave，以及 3 个 slave 的 `master_land_id`，否则 fail-closed；
7. 商店自动选种暂时跳过 2x2，首轮不会为了验证功能自动购买 2x2。

## 实机验收

源码合并后先运行纯本地测试和构建。真实 2x2 不需要手动铲地制造空位。

当当前作物自然成熟、自动收获后，如果至少形成一组完整 2x2 空位且背包里存在已识别的 2x2 种子，日志应出现类似：

```text
已按背包优先策略种植: 爱心果 2x2x1
```

随后“个人 -> 我的农场”应显示一个合种主地与三个合种副地。

若日志显示“检测到 2x2 种子，但当前没有完整 2x2 空地”，属于等待条件，不算失败。
